          Datenschutz & Speicher
          
    
          
      
          Datenschutzerklärung lesen
          
      
          Alles bleibt auf deinem Gerät
          
      
          Entwurf, Undo-Stand und Einstellungen liegen im lokalen Browserspeicher (localStorage), deine eigene Handschrift zusätzlich in IndexedDB dieses Geräts. Es gibt kein Konto, kein Tracking, keine Analyse-Skripte und keinen Server von Quillmark. Screenshots, OCR-Text und KI-Verarbeitung verlassen das iPad nicht – Ausnahme: der Server-Modus von Tizian, wenn du ihn einschaltest.
          
      
          
      
          
      
          Wichtig für iPadOS: Safari kann lokale Browserdaten bereinigen, wenn eine Website längere Zeit (ca. 7 Tage) nicht genutzt wird. Sichere deine eigene Handschrift deshalb als JSON-Datei (Handschrift → Sicherung). Zum Home-Bildschirm hinzugefügte Web-Apps sind davon in der Regel ausgenommen.

Wird erst beim ersten Screenshot-Import geladen.

          • Transformers.js 4.3.2 (@huggingface/transformers) – lokale KI über WebGPU. Quelle: cdn.jsdelivr.net (inkl. ONNX-Runtime-WASM). Wird erst nach Tipp auf „Lokales KI-Modell laden“ geladen.
            • 
        
          • Optionales Konto (Supabase Auth) – nur wenn du dich anmeldest oder ein Konto erstellst: Das Anmelde-Skript @supabase/supabase-js kommt von cdn.jsdelivr.net, E-Mail-Adresse und Passwort bzw. dein Google-Login gehen an den Anmeldedienst. Notizen, Bilder und Handschrift werden dabei nicht übertragen und bleiben nach dem Abmelden auf diesem Gerät.
            • 
        
          • Optionaler Server – nur wenn du „Text auf Server verarbeiten“ einschaltest: die von dir eingetragene Adresse (z. B. dein Hugging-Face-Space). Dorthin gehen ausschließlich die Texte, die Tizian bearbeiten soll.
            • 
        
          • KI-Modell onnx-community/Qwen2.5-0.5B-Instruct (quantisiertes ONNX). Optional onnx-community/Qwen2.5-1.5B-Instruct für bessere Lösungen. Quelle: huggingface.co. Nur nach deinem ausdrücklichen Klick; danach im Browser-Cache.
            • 
        
          • Keine weitere Bibliothek: ZIP, Apple-LZ4, TPL, Protobuf und PDF erzeugt Quillmark mit eigenem Code in dieser Datei (kein JSZip nötig) – der Export funktioniert auch offline.

          HTTPS-Hosting & Home-Bildschirm
          
    
          
      
          Quillmark ist eine einzige Datei: index.html. Öffnest du sie direkt aus der Dateien-App (file://), schränkt Safari Sicherheitsfunktionen ein: WebGPU (lokale KI), Web-Worker für die OCR, der Browser-Cache für Modelle und „Zum Home-Bildschirm“ funktionieren dann nicht oder nur teilweise.
          
      
          Deshalb: einmal kostenlos unter einer festen https://-Adresse ablegen
          
      
            
        
          1. GitHub Pages: Repository anlegen → index.html hochladen → Settings → Pages → Deploy from a branch → Adresse https://DEINNAME.github.io/REPO/.
            2. 
        
          2. Cloudflare Pages: Workers & Pages → Create → Pages → Upload assets → Ordner mit der Datei hochladen → Adresse https://PROJEKT.pages.dev/.
            3. 
      
          
      
          Auf dem iPad
          
      
            
        
          1. Adresse in Safari öffnen → Teilen-Symbol → „Zum Home-Bildschirm“.
            2. 
        
          2. Quillmark startet danach im Vollbild wie eine App; die Daten bleiben lokal.
            3. 
        
          3. Export: „Teilen / in Goodnotes öffnen“ wählen oder die Datei in „Dateien“ sichern und dort antippen → In Goodnotes öffnen → „Als neues Dokument importieren“.
            4. 
      
          
      
          WebGPU ist in Safari ab iPadOS 26 standardmäßig aktiv. Unter iPadOS 18 lässt es sich unter Einstellungen → Apps → Safari → Erweitert → Feature Flags einschalten. Ohne WebGPU bleibt nur die KI-Umformulierung deaktiviert.
